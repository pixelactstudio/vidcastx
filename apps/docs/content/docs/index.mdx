VidcastX is open-source (MIT), self-hostable video infrastructure in the style of Mux. You upload a video, a worker transcodes it into adaptive HLS with FFmpeg, and the output lands in your own S3-compatible bucket. Every component runs on machines you control:

- **API**: Elysia on Bun (`apps/api`, port 4001)
- **Dashboard**: TanStack Start (`apps/app`, port 4000)
- **Transcoder**: a Node worker that shells out to the FFmpeg CLI (`workers/transcoder`)
- **Infrastructure**: PostgreSQL (Drizzle ORM), Redis (BullMQ), S3 or MinIO
- **Auth**: Better Auth, with organizations and roles

## Current status

<Callout type="warn" title="Pre-release">
  VidcastX is in active development and is not production-ready. Nothing about deployment (containers, secrets, backups,
  observability) is codified yet.
</Callout>

| Area                            | State                                                                                                                  |
| ------------------------------- | ---------------------------------------------------------------------------------------------------------------------- |
| Auth and organizations          | Implemented: email/password, GitHub and Discord sign-in, organizations with members and roles.                         |
| Video library                   | Implemented: drafts, folders, metadata editing, pinning, soft delete and restore.                                      |
| Upload                          | Works: resumable S3 multipart uploads straight from the browser using presigned part URLs.                             |
| Transcode                       | Works: HLS ladder (1080p/720p/480p, never above the source except the 480p floor), poster JPEG and WebM hover preview. |
| Playback player                 | In progress for V1. The API already returns a signed URL for the master playlist.                                      |
| API keys                        | In progress for V1.                                                                                                    |
| Webhooks                        | In progress for V1.                                                                                                    |
| AI, live streaming, and billing | Database tables exist. No user-facing implementation.                                                                  |

The longer-term product direction lives in `IDEA.md` at the repository root. It describes where the project wants to go, not what the code does today. The prioritized work queue is in `TODO.md`.
